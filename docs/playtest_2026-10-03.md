# Playtest 2026-10-03: findings and fixes

The first multi-player playtest of the classic maps: public games with up to five
players, Slayer and CTF on BGL, BCK, DCN, DRL and LNG. Mods-v0.14.0, CE runtime 1.0.6.

Three problems were fixed for release beside this list (PR #136, launcher 0.10.2 and
mods 0.14.1):

- **Lobby buttons did nothing:** the player's UE4SS gave up at its stock 30 s scan limit,
  so no Lua mod ran. The launcher now enforces at least 120 s.
- **A Ctrl+R hot reload crashed the host:** the reload unloaded native DLLs whose hooks
  were still in the game. The DLLs now pin themselves, and the launcher turns hot reload
  off.
- **The lobby's event hooks now retry,** and a cooked lobby says when the mods didn't start.

Each issue below gives its cause, the evidence, the fix and its status. Line numbers are
as of `581c380`.

## 1. Frame drops, worst in CTF; flags change colour

**Measured (host, BCK CTF, two players).** Frames run at ~12 ms, then the game freezes
for ~250 ms every 3.24 s, followed by a ~110 ms present stall. Sampling the game thread
during those freezes put it inside UE4SS walking the whole object table:

- `FindAllOf` / `FindFirstOf`: ~19 ms each on a converted map.
- `StaticFindObject` of a path that isn't loaded: 18.7 ms, because a miss walks
  everything too. A loaded `/Script` path costs ~0 ms, a loaded `/Game` asset ~1.7 ms.

All 7 Mk V Classic mesh paths used for team armour were unloaded.

**Causes, worst first** (W = one ~19 ms object walk):

1. **The odd pass of MJOLNIRLevelLoader's CTF flags loop** (`main.lua:1630-1646`). The
   loop reschedules 1.5 s after it finishes, so the odd pass comes round every 3 s plus
   its own work.
   - It re-tints every Spartan and the local pawn. Each goes through `dressMeshes` →
     `resolveMesh`, which for each of the 7 unloaded Mk V meshes costs 1 W plus a
     `LoadAsset` and a blocking load.
   - It also re-arms the biped watch up to 3 times.
   - About 11-13 W per pass, which fits the ~250 ms freeze.
2. **`retintSoon`** (`:1455`): the same work 3 times after every spawn.
3. **Event sounds** (`:1193`). Nothing holds the waves, so after a garbage collection each
   play costs a walk plus a reload. This is the source of the irregular 60-190 ms bursts.
4. **Host relay and Lobby message hooks.**
   - `relayEvents` does a `FindAllOf("PlayerController")` per drain (`:1229`).
   - The Lobby's `ClientMessage` and `ServerExecRPC` hooks call `Net.isHost()` (a
     `FindAllOf`) for every message, before checking its type (`net.lua:89,96`).
5. **Lobby `watchHost`** (`Lobby/main.lua:2347`): every 5 s.

**Flag colours.** A flag that turns up away from both stands takes `Current.lastFlagTeam`,
which is the team of the last flag incident from either flag. Drains run every 100 ms and
reach clients only after the host's relay, so a dropped flag usually gets the previous
incident's team. The same rule produces the other symptoms:

- A carrier killed near a stand has the enemy flag dressed and pinned in the stand's team.
- The first-person flag is recoloured on any flag incident.
- `lastFlagTeam` and `HomeFlags` survive into the next match.

**Fix:**
- Cache resolved assets and their misses, and keep the found ones alive.
- Tint bipeds once per spawn, not every 3 s.
- Find controllers through the engine, not a `FindAllOf`.
- In the hooks, check a message's type before anything else.
- Give flags a team rule based on each flag's own state (home, carried, dropped).
- Reset flag state per world.

**Status:** code done, not yet tested in game (mods release):
- `resolveMesh` caches what it resolves (checked by name, since a handle does not keep
  its object) and skips paths that would not load until the next world.
- Unarmed watches retry at most every 10 s (`mayArm`).
- `Net.isHost` reads the local controller through the engine, and the Lobby's hooks
  check a message is one of theirs before anything else. The level loader's relayed
  sounds share the message type, so each one cost a client a walk.
- Flags:
  - A flag dropped near a stand counts as that stand's only if that team's flag isn't
    home.
  - A flag away from both stands waits up to 1.5 s for the flag incident after it.
  - The first-person flag takes the local player's own grab.
  - Flag incidents count even with no sound loaded.
  - Flag state resets per world.
- Every periodic loop (the level loader's `every`, the HUD tick, the Lobby's polls) now
  logs `slow: the <name> loop held the game thread N ms` for any run over 50 ms.

  A caveat for the measurement above: at that moment no `BP_SpartansBipedActor_C` existed
  and the biped watch had armed, so the Mk V re-dress may not explain all of that freeze.
  The next session's `slow:` lines will name the loop.

## 2. Weapons stuck in the ground

CE places netgame items and vehicles flush with the floor; 853 of 874 sit 0.001 wu above
it. Our bake creates every item "at rest" (placement flag `0x20`, `blam-cli/src/level.rs:1251`),
so the part of a weapon below its origin stays in the floor.

**Fix:** `tools/level/gen_ce_level.py`:
- Lift weapons and equipment by 0.05 wu.
- Lift vehicles without their own entry in `VEHICLE_LIFT` by 0.05 wu.
- Clear the at-rest flag on anything lifted, so it falls into place.
- Leave levitating powerups alone.

The maps need regenerating and re-baking.

**Status:** code done (`ITEM_LIFT`, `VEHICLE_LIFT_DEFAULT`, `NOT_AT_REST`); on Blood
Gulch every weapon, equipment item and non-Banshee/Scorpion vehicle now starts 0.05 wu
(15.24 cm) higher with the at-rest flag cleared. Needs the maps regenerated and re-baked.

## 3. "Slayer" again on the way back to the menu

**Cause (likely, client side).** At the menu, the level loader looks up the level file
from whatever scenario tag is still in memory: on a client, the map just left.
`loadLevelFile` skips its world check when given that key (`main.lua:267, 277-279`).

The loader then:
- rebuilds the old map's environment behind the menu,
- queues `player_spawn` once the menu pawn exists,
- and `playEvent` turns that into the game type's announcement.

The host's `running.txt` also outlives the match. It is only removed on the next switch.

**Fix:**
- Accept a tag's level only when it belongs to the current world.
- Never load a level for the Frontend.
- Clear the event queues on a world change.
- Remove `running.txt` when the menu comes up.

**Status:** code done, not yet tested in game:
- A scenario tag's level counts only on its own world or its canvas world.
- `FRONTEND` loads no level and removes `running.txt`.
- The event queues reset on every world change.

A client UE4SS.log from someone who heard it would confirm the cause
(expect `world FRONTEND has level ...`).

## 4. Vehicle lights blow out other vehicles, and don't light the level

**Cause.** Both halves come from deliberate choices:
- Converted terrain is on lighting channel 1 only, so only our sun reaches it
  (`main.lua:531-537`). The comment there explains why: headlights blew it out.
- Our levels force manual exposure at EV 0 under a 5-8 lux sun
  (`gen_ce_level.py:684`), while vehicle lights are tuned for the campaign's auto
  exposure, so they are many stops too bright here.

**Fix:**
1. Move our levels onto the campaign's exposure scale. Use `exposure_bias = -N` with sun
   and skylight intensity ×2^N. CE-drawn surfaces look the same, because the materials
   divide by exposure, and native lights and emissives drop to their intended brightness.
   N has to be chosen in game.
2. Then, optionally, put the terrain on channel 0 and keep the sun-share base colour from
   going black on faces turned away from the sun, so headlights light the ground.
   This needs a material cook.

**Status:** planned. It needs in-game tuning.

## 5. Covenant shields are one-sided, and bullets go through

These are the `c_field_generator` shields on DCN, GPH and RAT; maps with `teleporter_shield`
have the same rendering problem.

- **Drawing.** Transparent CE shaders (`schi`/`scex`/`swat`) map to `M_CE_Transparent*`
  masters that are never two-sided (`build_ce_materials.py:622-626`,
  `ce_material_spec.py:204-208`). A material instance cannot turn two-sided on, but CE
  draws these shaders double-sided.
- **Collision.** The shield's collision is converted and stops players and vehicles. But
  scenery triangles are added as surfaces that no BSP leaf references
  (`merge_ce_collision.py:19-22, 250`). Projectiles walk the bsp3d tree, so they never
  meet them. `ce_map_conversion.md` lists this as a known limit.

**Fix:**
- Two-sided variants of the transparent masters, chosen when the shader's two-sided bit
  (flags & 4) or `double_sided` is set. Needs a cook of chunk 988.
- Make scenery surfaces reachable by the tree. A `blam-sbsp` pass splits every leaf a
  scenery polygon touches on that polygon's plane, keeping the leaf's solid/empty state
  in both children, and adds a bsp2d reference. This also makes rocks and trees stop
  bullets, as in CE.
- Map `field_generator` to a material that stops projectiles.

**Status:**
- Materials: code done (`M_CE_Transparent{Add,Alpha,Mul}TwoSided`, chosen on the flag
  bit alone: halo2ue's `double_sided` is true for every transparent shader). Needs chunk
  988 cooked and the maps regenerated.
- Collision pass: planned, larger.

## 6. Every sniper kill is a headshot

The feed's "headshot" is the simulation's own flag, `DamageReportingInfo.Modifier == 1`
(`Hud/main.lua:88-94, 455`). The medals `headshot_kill` / `sniper_headshot_kill` come from
the same flag. Nothing we ship touches the sniper, the bipeds or damage:
- Megalo traits are all "unchanged".
- The Mk V swap is cosmetic and runs only in team games.

The log keeps one incident per name per match, so it can't count. The first sniper and AR
kills of each match were headshots: 2 of 2 and 3 of 3.

**Likely causes, ranked:**
1. Normal Reach behaviour, since only a head shot one-shots a shielded Spartan.
2. Aim assist and bullet magnetism steering rounds onto the head target.
3. The simulation's head section sits lower than the visible head.

**Next:**
- Count `kill` events by weapon and modifier in the hub's `match_events` for the playtest
  matches.
- Log every `Kill`'s weapon and modifier.
- Test live with the sniper's magnetism and autoaim set to 0 (weapons poke live), shooting
  a bot in the chest.

**Data (hub `match_events`, every public kill since 2026-10-03).** Headshot means
`modifier = 1`:

| Weapon | Headshot kills | Total kills | Headshot rate |
|---|---|---|---|
| Sniper rifle | 104 | 104 | 100% |
| Shotgun | 34 | 38 | 89% |
| Assault rifle | 27 | 31 | 87% |
| Pistol | 4 | 4 | 100% |

Explosives, melee and vehicles never get `modifier = 1`.

So it isn't the sniper, and it isn't aim: close-range shotgun kills are mostly body
shots, and the shotgun has little magnetism. The simulation flags nearly every lethal
bullet as a head hit, which rules out causes 1 and 2. What's left is the hit regions:
the Spartans model's head section, or how its damage sections map onto the biped's
nodes. One thing to check is whether an unshielded body hit lands on a section flagged
"headshot".

**Next:** the live test above (sniper and shotgun, body shots on a bot). Then read the
Spartans model's damage sections and their `headshot` flags in the tag editor.

**Status:** cause narrowed to the hit regions; needs a live test.

## 7. Event sounds late for other players

The path: host incident hook → host drain (100 ms poll) → `relayEvents` → reliable
`ClientMessage` per incident → client hook → client drain (100 ms poll) → `playEvent`.

| Source of delay | Cost |
|---|---|
| Waiting for each side's drain | up to ~117 ms each |
| The host's `FindAllOf` per relay | ~20 ms |
| Every incident is relayed, sound or not | 6 reliable messages for one sniper headshot |
| The wave reload after GC | tens to hundreds of ms |
| The client's own teleport | one more round trip, since the host has to see it first |

Typically 0.6-1 s in total. `NativeIncidents` is never reset, so a player who hosted
earlier hears no relayed sounds at all as a client.

**Fix:**
- Drain on the next tick after an incident or a relayed message.
- Find controllers through the engine.
- Relay only events that have a sound, batched into one message per drain.
- Keep waves loaded.
- Play the client's own teleport from its camera jump.
- Reset `NativeIncidents` per world.

**Status:** partly done, not yet tested in game:
- Done:
  - Both sides drain on the next tick.
  - The host relays only incidents with a sound, plus flag incidents.
  - The host reuses its controller list for 5 s.
  - `NativeIncidents` resets per world.
  - Played waves are cached.
- Still open: holding waves loaded across garbage collection, and detecting the
  client's own teleport locally.

## 8. Rocket Warthog: no gun, and the gunner goes invisible

`vehicles/rwarthog` maps to the Warthog's "rocket" variant (`gen_ce_level.py:55-58`). The
simulation attaches `warthog_rocket` (vehicle) and its `warthog_rocket_pod` weapon
correctly. But Campaign Evolved never shipped a rocket hog: the turret's tag wrapper has
no actor Blueprint, so nothing is drawn. The gunner's seat belongs to that turret, which
very likely hides the gunner too (unverified).

**Fix:**
- Stopgap: drop the variant, so rocket hogs spawn as chaingun hogs. Empty
  `VEHICLE_VARIANTS`, as `gen_bloodgulch_level.py` already does.
- Real fix: point `warthog_rocket-vehicle`'s wrapper at the chaingun turret's Blueprint
  (`ue-asset::tagwrap`), or a rewritten mesh with CE's rocket pod.

**Status:** stopgap code done (`VEHICLE_VARIANTS` is empty); needs the maps regenerated.
Real fix open.
