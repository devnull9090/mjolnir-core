# `mjolnir live objects`: every object in play, and who controls what

**Date:** 2026-09-29
**Summary:** `live objects` lists every object in the running game with its tag, position, health and shield; `live players` and `live arrays` show the rest of the simulation's tables.

The simulation keeps its objects, players, AI and script state in named
tables that it stores in its thread-local storage. `mjolnir` now finds those
tables directly. It reads the module's own TLS directory, and each table names
itself, so nothing is read at an address that one build hard-codes.

### Added

- **`mjolnir live objects [--group bipd] [--filter text] [--tsv out]`**: every
  object in play. Each row has its handle, its type (biped, weapon,
  equipment…), its definition tag, its position, its body and shield as a
  percentage of the maximum, and its parent if it is attached. The row for the
  unit a player controls is marked with that player.
- **`mjolnir live players`**: each player, the unit it controls, and where
  that unit is.
- **`mjolnir live arrays`**: all 59 of the simulation's per-game tables, with
  how full each one is. It needs no build profile.
- **`mjolnir live status`** also names the simulation thread and says how many
  objects are in play.

### Known limits

- Read only. Positions and vitality can be read but not yet written.
- An attached object's position is relative to its parent.
- The layout inside an object was measured on the current Steam build (CU4).
  A game update that moves it is caught by a consistency check, and the
  command stops instead of printing wrong values.
